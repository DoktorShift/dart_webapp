# P2.03 Gerät verbinden und Geräteliste

**Status:** In Prüfung (Bau abgeschlossen; Abnahme auf echten Geräten offen)
**Paket:** P2 · **Planstelle:** [PLAN.md](../PLAN.md), Zeilen 105–129 („Geräte einfach per QR verbinden“); Entscheidung 0002 §7; Recherche DR-08 bis DR-12, DR-18

## Ziel

Ein neues Handy, Tablet oder Computer bekommt das eigene Profil vom vorhandenen Gerät: ohne Server, ohne Protokollwörter, mit einer Prüfkennung auf beiden Bildschirmen und einer ausdrücklichen Freigabe auf dem Gerät, das das Profil hat. Die Geräteliste zeigt, welche Geräte das Profil haben, und sagt ehrlich, was Entfernen bedeutet.

## Produktregeln und Abnahmekriterien

- Betroffene Kriterien: A06 (kein Hauptschlüssel über einen Board-QR), A07, A08.
- [Entscheidung 0002](../../decisions/0002-architektur.md) §7: Kopplung nur aus „Eigenes Gerät hinzufügen“, flüchtige Nachrichten (21180) NIP-44 zwischen Einmalschlüsseln, dieselbe Prüfkennung auf beiden Geräten, Paket erst nach Bestätigung, „Dein Profil ist dabei.“ erst nach der Rückmeldung des neuen Geräts, Wiederholung bis Bestätigung oder Ablauf (10 Minuten). §10: ein verlorenes Gerät lässt sich nicht widerrufen; die Liste ist informativ.
- Vertrag: [docs/protocol/families/pairing.md](../../protocol/families/pairing.md) (Nachrichten, Code, Prüfkennung, jetzt auch das Profilpaket).
- [Designregeln](../../../../_coordination/NOSTR-DESIGN-RULES.md): kein geheimer Schlüssel in Anzeige oder Eingabe; Fehler mit einem nächsten Schritt; Darts-Abend-Test (eine Hauptaktion, große Prüfkennung).

## Fehlerfälle

| Fall | Verhalten | Prüfung |
| --- | --- | --- |
| Prüfkennung stimmt nicht | „Nein, abbrechen“ / „Ablehnen“: beide Seiten enden („abgelehnt“), nichts wurde übertragen, „Neuen Code zeigen“ | `tests/relay/devices.test.ts` |
| Abgelaufener oder zu lang gültiger QR (Screenshot) | wird vor jeder Nachricht abgewiesen („Dieser Code ist abgelaufen“) | `tests/relay/devices.test.ts` |
| Jemand sieht die Ankündigung des Code-Wegs und antwortet ohne Code | MAC fehlt: verworfen, das neue Gerät wartet weiter | `tests/relay/devices.test.ts` |
| Wiederholte oder nachgespielte Nachrichten | eine beendete Kopplung nimmt nichts an; eine neue gehört zu einer anderen Sitzung; wiederholte `hello`/`accept` ändern nichts | `tests/relay/devices.test.ts`, `lib/devices/pairing.ts` |
| Reload mitten im Vorgang (beide Seiten) | dieselben Codes bzw. dieselbe Prüfkennung, der Vorgang läuft weiter | `tests/relay/devices.test.ts` |
| Inzwischen anderes Profil auf dem neuen Gerät | „Hier ist inzwischen ein anderes Profil angemeldet“ (`SessionError "occupied"`), Abbruch an das andere Gerät | `lib/devices/pairing.ts` |
| Paket passt nicht in eine Nachricht | Name und Relay-Liste werden zuerst weggelassen; sonst „passt nicht in eine Übertragung“ mit Verweis auf die Sicherungsdatei | `lib/devices/pairing.ts` (`packageData`) |
| Falscher Code oder Board-Code | Antwort an Ort und Stelle („kein Code zum Verbinden eines Geräts“), Scannen geht weiter | Browserlauf |
| Kein Profil auf dem Gerät, das den Link öffnet | „Kein Profil auf diesem Gerät“ | `components/devices/add-device-screen.tsx` |

## Offen

- Abnahme auf echten Geräten (iPhone ↔ Android, Handy ↔ Tablet, Browser und installierte App, gesperrte Kamera, Link im falschen Browser, Signer-App im Hintergrund) und über öffentliche Relays (Nutzerfreigabe nötig).
- Der Weg „Signer-App“ am neuen Gerät ist gebaut, aber nur als Einheit getestet (kein Durchlauf mit nak bunker im Browser).
- Zwei Geräte, die sich gleichzeitig in die Liste eintragen, verlieren einen Eintrag (neueste Version gewinnt); die Liste ist informativ, ein fehlender Eintrag kostet nichts.
