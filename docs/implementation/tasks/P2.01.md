# P2.01 Kontextprofil und Ansichten

**Status:** Umgesetzt, Nachweis offen: echte Geräte, Safari, VoiceOver, Nutzertest (A21, A29), integrierte HIG-Prüfung
**Paket:** P2 · **Planstelle:** [PLAN.md](../PLAN.md), Zeilen 71–104 (Nutzerwege), 317–339 (Profilansicht); Entscheidung 0002 §4, §9

## Ziel

Aus einem fertigen Spiel entsteht mit einem Tipp ein Profil, das nur die Spiele des gewählten Platzes übernimmt und nur Name, Bild und Relay-Liste veröffentlicht. Der Profil-Tab zeigt angemeldet eine Sportkarte mit nachvollziehbaren Zahlen; fremde Profile lassen sich über Link oder Spielverlauf ansehen, Gäste sehen eine lokale Spieleransicht statt eines erfundenen Profils.

## Produktregeln und Abnahmekriterien

- Betroffene Kriterien: A02, A05, A10, A21 (Profilteile).
- Gast zuerst: kein Anmeldedialog, das Angebot ist eine ruhige Zeile im Ergebnis, nach „Später“ für dieses Spiel weg, nie bei unbenanntem Training.
- Nichts Privates wird veröffentlicht; die Statistikkarte ist ausdrücklich einzuschalten (Standard aus) und als „Vom Spieler geteilt“ gekennzeichnet.
- Namen nie mit „…“ gekürzt; Profilnamen bis 50 Zeichen, auch im Spielbildschirm vollständig.
- Designregeln (`_coordination/NOSTR-DESIGN-RULES.md`): kein geheimer Schlüssel in irgendeiner Form, Relays nur unter „Erweitert“ als Hostnamen mit Zustand, NIP-05 nur nach Prüfung, gleiche Namen mit Kennung.

## Review Runde 1 (2026-10-06)

| Befund | Behandlung |
| --- | --- |
| hoch: Bearbeiten/Erweitert überschrieben ein nicht geladenes Profil | `lookupOwnEvents`/`changeBase`: Nachsehen je Seitenaufruf und vor jeder Änderung; ohne Kopie und ohne antwortendes Relay Ablehnung („konnte nicht geladen werden“, Erneut versuchen); „nichts gefunden“ wird vor dem Schreiben gesagt; Profilkarte „Wird geladen“/„Nicht geladen“ statt „Ohne Namen“ |
| hoch: nächstes Spiel zählte nach dem Mitnehmen nicht | Mitnehmen benennt den Spieler nicht um; „Du“ in der Einrichtung (per Profil verbunden); Platznamen auf 16 Zeichen |
| hoch: Anmelden ersetzte eine andere Sitzung stillschweigend | `SessionOptions.replace`, `SessionError "occupied"`, Dialog mit Warnung; wartende Signer-Anfragen werden bei jedem Start gelöscht |
| mittel: alter Name nach Profilwechsel, doppelte Spieler | `useOwnEvents` je Profil; `addProfilePlayer` atomar (feste Id, `putNew`); automatischer Spieler aus dem öffentlichen Namen entfällt |
| mittel: lange Namen im Spielbildschirm abgeschnitten | 16 Zeichen je Platz (`MAX_SEAT_NAME`), Nachweis mit sechs Plätzen |
| mittel: Anlegen/Bearbeiten warteten auf Relays | `submitOwn`; das Mitnehmen-Blatt bleibt bis zum Ende offen |
| mittel: Statistik-Freigabe hielt nicht ohne Spiele | eigene Einstellung je Profil, Karte folgt den Zahlen |
| mittel: „Zum Spiel hinzufügen“ fehlte am fremden Profil | gebaut (nachgeordnet unter „Profil teilen“; während die Einrichtung offen ist, kann kein Profil sichtbar sein, dort bleibt der Scan-Bogen die Hauptaktion) |
| mittel: Einrichtung weckte bei jedem Öffnen den Signer | Signer nur für noch nie gelesene Runden |
| mittel: Abmelden-Dialog mit blauer Zerstörungstaste | beide Wege rot, Abbrechen bevorzugt, Titel „Abmelden ohne Sicherung?“ |
| niedrig | Mitnehmen-Text ohne Versprechen; Runden nur mit Profil des Platzes; Relay-Entfernen fragt; höchstens vier eigene Relays; `isPubkey` und noble-Hex statt Kopien (`lib/nostr/pointers.ts` behält seine Prüfung: keine Abhängigkeit von `lib/storage`); „Speichern“, englisch „updated today“; Verlauf |

## Review Runde 2 (2026-10-16)

| Befund | Behandlung |
| --- | --- |
| hoch: der Wechsel-Dialog antwortete zweimal (die Aktion ist ein Radix `DialogClose`), jede bestätigte Ersetzung lief den Abbruch-Pfad | Ursache im Dialog: die Aktion verhindert das Schließen durch Radix (`preventDefault`) und antwortet ja; der Wächter nimmt den Dialog weg; Abbrechen, Escape und Hintergrund antworten nein. Kein Merker. Nachweis: Link-Variante erreicht die Profilwurzel, die Signer-App unterschreibt danach (Kind 0 auf dem Relay, 811 ms); Anlegen-Variante: Formular weg, Profil-Tab zeigt das neue Profil, genau ein Spieler |
| mittel: nach „Name im Spiel“ zählte das nächste Spiel nicht, „Du“ daneben | Einrichtung füllt die Plätze aus dem letzten Spiel über die Spieler-Ids (`loadLastGame`), aufgelöst über das Verzeichnis, sobald es gelesen ist; „Du“ verschwindet, sobald ein Platz den eigenen Namen trägt; `loadLastPlayers` entfällt (die Liste wird für 1.0.0 weiter geschrieben) |
| mittel: Speichern wartete auf das laufende Nachsehen (offline 7,4 s) | `changeBase`: mit bekanntem Stand höchstens 1,5 s, offline gar nicht; das Blatt sieht beim Öffnen nach, nicht beim Einhängen der Profilansicht. Nachweis: offline 818 ms, Relay hängend 2354 ms (Laborwerte) |
| mittel: ein teilweises Nachsehen galt als vollständig („nichts gefunden“, neues Kind 0 über ein unerreichbares) | `OwnLookup` ist `asking`, `complete` oder `incomplete` mit den Relays ohne Antwort; „nichts gefunden“ nur bei `complete`; sonst „nicht vollständig geladen“ mit Erneut versuchen, kein öffentliches Speichern ohne Stand (Name im Spiel bleibt änderbar); Erweitert nennt die Relays ohne Antwort und bietet die App-Relays nicht als neue Liste an; ein unvollständiges Nachsehen wird beim nächsten Mal von selbst wiederholt |
| niedrig: alter Code nach abgebrochener Ersetzung | `drop` des Codes startet eine neue Runde (neuer Code), die alte Verbindung wird geschlossen |
| niedrig: Fehler des Wechsels verschluckt | der Wächter löst das Anmelde-Versprechen mit dem Versprechen des Wechsels auf; die Aufrufer zeigen den Fehler |
| niedrig: Gäste luden Code der angemeldeten Ansicht | Profilwurzel lädt die Ansicht lazy, das Ergebnis trägt nur die Zeile, der Wechsel-Dialog lädt bei Bedarf; Gastprüfung über alle geladenen Chunks ohne Marker |
| niedrig: „12 Monate“ brach bei 320 px um | „Gesamt / 1 Jahr / 30 Tage“, englisch „All / 1 year / 30 days“, Verlauf „Ø des Jahres davor“ |
| niedrig: Nachweis-Skripte (Port, ungenutzte Importe) | `blackhole.py` liest den Port aus `RELAY_PORTS`, Importe entfernt, Lint ohne Warnungen |
| niedrig: eingefügte Verbindung ohne Besitzer | wird beim Verlassen des Schritts geschlossen, solange sie nicht behalten wurde |
| niedrig: Profilbildschirme offline nicht ladbar | `warmProfileScreens` (register.ts) lädt Statistik, Spiele, Spieldetails, Spieleransicht und Erweitert vor, sobald ein Profil da ist |

Nicht geändert: „Zuletzt gespielt“ in der Einrichtung bietet Namen aus dem Spielverlauf an (1.0.0, `recentPlayerNames`), nach einer Umbenennung also auch den alten; außerhalb dieses Bereichs.
